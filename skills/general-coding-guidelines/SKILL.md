# General Coding Guidelines

## Comments

* Self-explanatory code is better than comments. 
* Don't include conversation or specification's context in comments.
* Write comments for non-obvious code, describe what it does, and why doing it.
* Keep concise, 1-2 liners are ideal, use longer comments or include examples if necessary, e.g. sample data for complicated data transfer.
* Function comments should describe the function's purpose, inputs, outputs, and assumptions. Implementation details should be in the code itself.
* If not specified in the repo, comments length should be limited to 120 characters per line.
